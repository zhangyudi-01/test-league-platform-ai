# Data Closure Finalization Extension

## 继承规则

- 最终 TP 的 `Data Closure Refs` 必须等于其所有 Source Candidates 引用的闭包并集。
- 精确重复候选合并时不得丢失任何数据路径；同一 TP 可以引用多张闭包卡。
- 不得在模块汇总阶段首次添加 DC。若候选应依赖某闭包但没有引用，回退对应 RSU 重新生成和校验。
- 对照闭包复核数据库相关候选是否覆盖关键过滤、断链/空数据、重复映射、读写影响和跨层一致性；来源支持但候选缺失时按上游缺口处理。

## 去重边界

- 数据路径、过滤口径、写入目标或数据库状态是否形成独立测试点，应由需求表达的业务行为和可独立判定结果决定。
- 你是高级测试工程师。数据路径、过滤口径、写入目标和数据库观察若对应不同操作、对象、状态迁移、业务结果或可独立定位的缺陷，就应拆分；只有同一操作下的等价输入或共同证据才合并。
- finalization 默认一候选一 TP；只有 `测试项`、完整 `测试点` 和 `备注` 忽略排版空白后均完全重复时才自动合并。
- 合并后必须保留全部 Source RSUs、Source Candidates、Question Refs、Context Refs 和 Data Closure Refs。
- 必要数据条件和判定结果写在 `测试点`，闭包路径写在引用列；不得将关键断言藏在备注，也不得把多个独立业务行为压进同一个测试点。
