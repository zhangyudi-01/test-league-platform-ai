# RSU 模块生成规划规则

1. 复杂度是本次测试点生成的调度判断，不是需求事实；不得修改 preanalysis 文件。
2. 普通 RSU：主要风险与结果边界清楚，不依赖跨状态时序、并发竞态、轮询闭环、冲突依赖或显著跨段组合。
3. 复杂 RSU：存在跨状态时序、并发/锁、轮询/超时/重试、短路链路、冲突动态依赖，或必须独立聚焦才能可靠判断的宽语义契约。
4. 复杂 RSU 必须单独成批。普通且上下文签名相同的 RSU 可成批，目标每批 4～6 个，最多 10 个；不足 4 个合法，不得为凑数跨签名组合。
5. 每个 RSU 必须且只能分配一次，顺序保持 RSU map 顺序；批次 ID 按首次出现连续编号。
6. 候选数量不是复杂度判据，也不是规划目标。简单 RSU 仍可产生 0～N 个必要候选，复杂 RSU 也不得为显示复杂而扩写。
