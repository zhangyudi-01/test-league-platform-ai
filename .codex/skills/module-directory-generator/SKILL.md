# 模块目录生成 Skill

当用户需要根据需求文档、PRD、功能说明或其他源文档生成模块目录结构时，使用本 skill。

本 skill **只负责生成和创建目录结构**，不负责把需求正文拆分到目录中。正文拆分请使用 `requirement-document-splitter` skill。

## 适用场景

- 根据需求文档中的功能模块生成 `modules/` 目录。
- 根据文档章节结构生成带唯一 ID 的目录树。
- 为后续原子需求拆分、测试设计、用例管理准备目录骨架。

## 不适用场景

- 已经有确认好的模块目录，只想把需求正文拆进去。
- 想生成测试点、测试方案、测试用例。
- 想对需求进行总结、改写或详细分析。

## 输入信息

执行前需要确认：

1. 源文档路径。
2. 要参考的章节范围。
3. 目标目录根路径。
4. 目录前缀，例如 `MOD`。
5. 需要保留的层级深度。
6. 是否只生成目录计划，还是确认后直接创建目录。

如果这些信息不明确，先询问用户，不要猜。

## 核心原则

1. **源文档是唯一依据**：目录名称必须来自源文档。
2. **禁止乱加文字**：不要添加 `管理`、`模块`、英文缩写等源文档中不存在的内容。
3. **只创建目录**：不要创建 README、`.gitkeep`、说明文件或占位文件。
4. **不遗漏层级**：源文档有几级，就按确认范围创建几级。
5. **唯一 ID**：目录名建议使用 `{前缀}-{层级ID}-{源文档名称}`。
6. **先计划后创建**：目录树计划应先展示给用户确认。

## 推荐目录命名

```text
{前缀}-{层级ID}-{源文档名称}
```

示例：

```text
MOD-01-登录/
MOD-02-封存验奖工具/
  MOD-02-01-刻录/
    MOD-02-01-01-任务查询/
```

## 执行流程

### 步骤 1：读取源文档指定章节

只读取用户指定的章节范围。不要把历史资料、测试资料或其他背景资料混进目录命名依据。

### 步骤 2：提取层级结构

根据标题、编号、列表层级识别模块树。

需要保留：

- 原始模块名称。
- 父子层级。
- 源文档顺序。

### 步骤 3：生成目录计划

先输出类似下面的计划：

```text
目标目录：<modules_root>

MOD-01-xxx/
MOD-02-yyy/
  MOD-02-01-zzz/
```

同时说明：

- 共多少个一级目录。
- 共多少个叶子目录。
- 是否存在无法判断的层级。

### 步骤 4：等待确认

用户确认前，不创建目录。

如果用户指出命名问题，按用户反馈调整计划，不要辩解，也不要保留错误命名。

### 步骤 5：创建目录

确认后只创建目录结构。

禁止：

- 创建 README。
- 创建占位文件。
- 创建需求正文文件。
- 改源文档。

## 质量检查清单

完成后检查：

- [ ] 目录名称与源文档一致。
- [ ] 未添加源文档没有的词。
- [ ] 层级没有遗漏。
- [ ] ID 连续且无重复。
- [ ] 只创建目录，没有创建文件。
- [ ] 目标路径正确。
