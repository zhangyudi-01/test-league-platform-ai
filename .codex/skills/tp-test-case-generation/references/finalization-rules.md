# 模块归并规则

## 进入条件

只有全部批次和 TP 用例通过校验，才可生成最终文档。最终阶段是确定性拼接，不再调用 AI 归并、扩写或改写正文。

## 确定性收录

- 按最终 TP 顺序、再按来源 TC 顺序逐条收录。
- 只把 `TC-TP-*` 换成连续的 `TC-MOD-*`，其余标准用例单元格逐字保留。
- 每个来源用例恰好出现一次；每个 TP 至少被一个最终用例覆盖。
- 去重和范围控制在批次生成阶段完成，最终阶段不得补救性语义合并。

## 无损追溯

- 每一个 `TC-TP-xxx-xxx` 必须在模块追溯索引的 `Source TC-IDs` 中出现且只出现一次。
- 每条最终追溯行必须对应一条标准测试用例行，`Final TC-ID` 与标准表首列一致。
- 最终引用必须是来源用例引用的并集，不能新增输入包外的业务事实，也不能在归并时丢失引用。
- 最终 SQL Refs 从标准用例正文提取，必须与来源逐条一致。
- 最终校验复用 SQL 阶段的 `EXPLAIN` 报告，并核对 SQL manifest、SQL 文件和报告指纹仍一致；不会重复连接数据库。任一 SQL 资产变化后必须回到 SQL 阶段重新校验。

## 覆盖矩阵

`coverage-matrix.md` 对每个最终 `TP-ID` 恰好一行。每行至少关联一个 `TC-MOD-*`，状态固定为 `covered`；说明可简述该 TP 的场景如何由最终用例覆盖。

## 输入漂移

归并输入由全部已验证 `by-tp` 文档的路径、哈希和用例数计算。来源文档、上游最终 TP、就绪性文档或执行上下文发生变化时，旧归并产物必须归档并重新准备；不能在旧输入哈希上继续编辑或校验。
