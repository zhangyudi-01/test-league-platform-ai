# 输出契约

## TP 用例文档

文件固定为 `by-tp/<TP-ID>.md`，只允许一份。必须按下列章节和表头输出：

```text
# <TP-ID> - 测试用例
## 生成元数据
字段 | 值
## 用例追溯索引
TC-ID | 覆盖场景 | TP-ID | RSU Refs | Question Refs | Context Refs | Data Closure Refs | Data Profile Refs | 用例设计说明
## 标准测试用例
TC-ID | 冲刺 | 测试项 | 测试点 | 数据变量 | 前置条件 | 执行步骤 | 备注 | 预期结果 | 测试结果1 | 测试结果2 | 测试结果3
```

### 元数据

元数据表必须包含：

```text
TP-ID | <当前 TP>
输入 SHA-256 | <输入包中的哈希>
生成结果 | validated
```

模板占位符、空白必填单元格、非规范 ID 一律不能通过校验。

文档中的 `生成结果=validated` 是待校验的输出声明，不代表校验已通过；`generation-state.json` 的 validated 状态只能由对应校验脚本写入。表头、列数和 Markdown 分隔行必须保留，冲刺、备注等不适用的必填项填 `无`，不得留空。

### 追溯索引

- `TC-ID` 与标准测试用例首列逐行一一对应。
- 每个 TP 的用例数量由逐项拆分评估决定，不设 `1 TP = 1 TC` 默认值。只有独立业务风险、不可合并前置或操作、独立可判断预期、独立回归价值四项同时成立时才允许拆成多条；每条追溯索引的“用例设计说明”必须写成 `独立业务风险=...；不可合并前置或操作=...；独立可判断预期=...；独立回归价值=...`，四项均为当前用例的具体非空理由。未同时成立时合并可执行验证，但仍须覆盖当前 TP 的全部测试承诺。
- `TP-ID` 必须等于当前 TP。
- `RSU Refs` 必须是当前 TP 的来源 RSU 子集，且至少一个。
- `Question Refs` 可为当前输入包提供的 `Q-*`、`CIQ-*`，无引用时填 `无`。
- `Context Refs` 只能使用当前输入包中的资源；无引用时填 `无`。
- `Data Closure Refs` 可保留当前 TP 实际使用的 DC；只有实际采用某个 Profile 时才填 `Data Profile Refs`。引用 DC 不等于必须填 DP 或写 SQL。
- `数据变量` 填写一个或多个“字段描述 + `$变量`”，多个变量用中文或英文分号分隔；字段描述的语言、大小写、空格、下划线和命名风格不受限制，也不强制填写示例。不用变量时填 `无`。每条声明必须恰好包含一个变量且字段描述非空。
- 数据变量须在前置条件或执行步骤实际使用；SQL 参数绑定同名变量，预期不重复参数。
- 前置无要求填 `无`；简单条件可直接一句，复杂多类信息才使用有意义的分类。不得为了格式制造“场景状态/场景参数/准备校验”。
- 执行步骤与预期结果都逐项独占一行，从 `1.` 连续编号，数量一致且一一对应。
- 表格单元格中的多条前置条件、执行步骤和预期结果用 `<br>` 分行；物理换行或把多项编号写在同一逻辑行不能替代它。
- 所有用例的预期结果必须逐项独占一行，使用 `1.`、`2.`、`3.` 形式从 1 连续编号；只有一项时也必须以 `1.` 开头，不允许出现未编号的首段、尾段或夹杂行。
- `测试结果1`、`测试结果2`、`测试结果3` 是必填列；当前仅生成测试用例、尚未执行测试时三列统一填写 `未执行`，不得留空。
- `SELECT` 放在步骤，预期简洁写与具体 SQL-ID 查询结果一致。用例阶段不生成 DML；入库/更新预期描述记录内容。
- 正文禁止“当前 TP”“来源场景”“场景矩阵”“数据闭包执行计划”“核心操作”等内部占位话术。

## 模块归并文档

`module-test-cases.md` 固定含元数据、模块用例追溯索引和标准测试用例。脚本按 TP 顺序逐条收录已验证来源用例，只改变最终 TC-ID，不由 AI 改写或合并正文。

## SQL 资产引用

数据库 TP 使用的 SQL 原文必须独立保存于 `sql/<SQL-ID>.sql`，并在 `sql/sql-manifest.json` 注册。执行计划的 `SQL Refs` 只填写 SQL-ID；相同 SQL-ID 可以被多个来源用例和最终模块用例复用。

每个 SQL 引用必须同时满足：

- SQL-ID 必须存在于已验证 generation plan 和 manifest，文件名对应，且分配给当前 TP。
- `SELECT` 出现在步骤和预期；预期只需说明页面/接口展示与该 SQL 查询结果一致。
- 参数绑定写成 `:参数名=$同名变量`。新规划 SQL 只允许 `SELECT`。

SQL 阶段对全部计划 SQL 执行一次 MySQL `EXPLAIN`；批次和模块最终校验只复核报告与当前 SQL/manifest 指纹一致，不重复执行数据库校验。报告不嵌入 SQL 密码。

`coverage-matrix.md` 固定表头：

```text
TP-ID | Final TC Refs | 状态 | 说明
```

每个最终 TP 恰好一行，至少引用一个 `TC-MOD-xxx`，状态填 `covered`。
