# TP 测试用例生成 Skill 优化记录

本文记录 `tp-test-case-generation` 的功能演进、运行中发现的缺陷、修复方案、最终能力和验证结果。它用于回答“为什么这样设计、某个行为何时改变、问题实际修在哪里”，不替代 [SKILL.md](./SKILL.md) 的执行约束或 [README.md](./README.md) 的使用说明。

## 维护规则

- 功能新增、缺陷修复、默认值变化、兼容性变化或重要使用约束调整，在实现落盘且完成相称验证后，于同一个 turn 追加记录。
- 编号固定为 `TP-OPT-xxx`。追加前完整读取本文，以最大现有编号加一；不覆盖、删除、重排或改写旧行。后续再次调整同一问题时新增一行，并在“关联”中引用旧编号。
- “类型”可区分 `需求`、`缺陷`、`安全性`、`兼容性`、`文档` 和 `关联上游修复`；“归属”明确实际修改位于当前 Skill、上游 Skill、模块产物还是仅为使用方式。
- “问题或需求”保留本窗口/当前会话中实际遇到的现象和触发背景；“修复或实现方案”只写实际落盘内容；“实现能力 / 结果”不得把计划写成完成。
- 验证必须写真实执行过的测试、命令或产物检查。没有自动验证时明确写“人工检查”，不能使用含糊的“已验证”。
- 用户可见流程、命令、参数、默认值、状态、输出、恢复方式或限制发生变化时，同步更新 [README.md](./README.md)。仅内部重构且用法不变时可不改手册。
- 尚未修复的观察、失败实验、推测、纯讨论和普通模块业务数据问题不写入完成历史。若 TP 流程暴露的问题实际修复在上游，可追加“关联上游修复”，但必须写清归属和关联文件。
- 日期采用仓库所在时区的自然日。“实时记录”指修复完成的同一个 turn 内追加，不代表后台监听或自动扩大维护权限。
