## 定位

本卡保存列表接口跨来源组装的业务链路和可复用断言语义，不保存需求原文或正式步骤。

## 关联来源

- SRC-API-BACKEND: /sporttery/match-monitor
- SRC-CODE-MONITOR: listMatchMonitor、readFootballMatches、readBasketballMatches、enrich
- SRC-CODE-RULES: footballScore、basketballScore、rowColor、taskType
- SRC-DB13: 竞彩足球/篮球赛程、联赛、球队、事件、任务、备注表设计

## 系统链路

竞彩足球/篮球赛程 -> 联赛和球队名称 -> sport_id + s_match_id 读取标准比赛 -> sport_id + 官方 match_id 读取事件和备注 -> 组装排名、状态、比分、开奖、计数和颜色。本期不使用任务表。

## 链路理解

- 赛程绿色背景对应的事件标题为“比赛方变更”；这是对需求原文中“球队变更”的最新确认，见 [API-001 问题清单第 11 项](../../interfaces/API-001-get-match-monitor/clarification-questions.md)。
- 竞彩源比赛是列表主体；标准化比赛缺失时仍保留源行，状态为未匹配，标准字段为空。
- 足球和篮球官方比赛 ID 不能跨 sport_id 解析；事件和备注也按 sport_id 隔离。
- 球队名称与竞彩源比赛表的主客队顺序一致；排名等 s_match 来源字段按 if_change 转成竞彩主客队顺序。官方已开奖比分已经是竞彩顺序，不再应用 if_change；标准化比分按 if_change 转换。
- 事件计数来自竞彩事件表。事件详情按 sport_id 和竞彩官方 match_id 查询，不分页返回全部匹配事件，按创建时间、事件 ID 倒序展示；标题取 `event_name`，详情取 `reason_desc`。本地旧实现还按 SPORTTERY 来源过滤；没有开售前后时间筛选。
- 已开奖只使用竞彩比分，部分或全部为空均不以标准比分补齐；未开奖使用标准比分并按 if_change 对齐。篮球取 home_score/away_score；两项目移除 periods，篮球 half 为 null。具体见[接口问题清单](../../interfaces/API-001-get-match-monitor/clarification-questions.md)。
- 行颜色涉及事件 `reason_title` 和更新时间，无事件为 NONE；本期不使用任务或解除状态。
