## 定位

状态：`test-point-ready`。本卡记录 API-001 用户确认的目标语义，不代表当前竞彩列表已经查询或返回该对象；当前实现和环境执行情况见“当前缺口”。

## 关联范围

仅覆盖 API-001 列表项的 `beitaiFootballMatchLiveDTO`；标准比赛、列表筛选及其他聚合沿用模块 DC-001。列表状态对象不等同于 API-002 的进程事件数组。

## 闭包目标

说明竞彩足球列表行如何经标准比赛关联贝泰 live 行，原样返回直播状态和时钟；标准比赛或 live 缺失不应删除竞彩列表行。

## 输入与输出

| 对象 | 关键字段 | 语义 |
|---|---|---|
| 竞彩足球赛程 | `s_match_id` | 列表主体；足球运动项目由来源表及列表组装的 `sportId` 确定，标准比赛关系复用 DC-001 |
| 标准比赛 | `match_id`、`sport_id`、`replace_id`、`beitai_match_id` | 在匹配的足球标准比赛中取得贝泰比赛 ID |
| 贝泰 live 行 | `match_id`、`status`、`match_status`、`match_clock`、`stoppage_clock` | `match_id` 是贝泰比赛 ID 和主键 |
| 列表直播对象 | `matchId`、`status`、`matchStatus`、`matchClock`、`stoppageClock` | 分别对应 live 行的同义字段，保留原值和空值 |

## 关系图

```text
竞彩足球赛程.s_match_id
  -> s_match.match_id（s_match.sport_id=足球；已替换时追随新比赛 ID）
  -> s_match.beitai_match_id
  -> beitai_football_match_live.match_id
  -> 列表项.beitaiFootballMatchLiveDTO
```

## 表角色

| 物理表 | 角色 | 访问与所有权 |
|---|---|---|
| `sporttery_football_match` | 竞彩列表主体及标准比赛引用 | 当前接口只读；竞彩采集数据 |
| `s_match` | 标准比赛及贝泰来源 ID | 当前接口只读；标准化比赛数据 |
| `beitai_football_match_live` | 五字段原始来源 | 当前接口预期只读；贝泰采集数据，`match_id` 为主键 |

## 连接与过滤契约

- 竞彩来源到标准比赛的 `s_match_id`、运动项目及有效记录约束沿用 DC-001；标准比赛缺失时保留来源行。
- 足球直播对象的目标关联为 `s_match.beitai_match_id = beitai_football_match_live.match_id`；live 主键保证同一个贝泰比赛 ID 至多一条记录。依据是用户确认沿用历史列表、历史服务及旧列表测试；本地子模块 `95884a32` 未体现该关联，用户反馈的修复版本待核验。
- 历史服务按足球比赛收集贝泰 ID 后查 live，未按标准比赛状态过滤；用户提供的 `closed`/`ended` 示例也不应被当成必须处于比赛中的限制。篮球不使用足球 live 表。

## 数据状态与准备契约

- 后续准备数据时需明确竞彩官方比赛 ID、标准比赛 ID 和贝泰比赛 ID 的不同作用域，以及三者的关联；不能假定它们相等。
- 相关数据状态包括有效 live 行、来源 ID 或 live 行缺失、字段源值为 `null` 或空字符串，以及非足球列表行；具体样本和写入方式留给自动化设计。
- `status` 和 `match_status` 是独立列，不能根据其中一个值推导另一个；live 对象不因 `if_change` 转换主客方向。

## 查询与断言契约

有对应足球 live 行时，对象五字段分别映射该行；没有有效标准比赛、贝泰 ID 或 live 行，以及非足球记录，按用户确认沿用的历史列表行为返回对象 `null`。源字段 `null` 与 `""` 原样区分；顶层 `matchStatus` 是标准比赛数值，与对象内字符串 `matchStatus` 不同。页面对比赛时钟的格式化不属于对象字段映射。

## 清理与隔离

后续测试需识别自造记录与共享记录：仅清理本次拥有的 live 数据；若临时修改现有 live 行或标准比赛关联，应在失败路径也恢复原值。具体 owner、主键及清理顺序由自动化实施方案确定。

## 当前缺口

- 用户反馈开发已修改完成；本地子模块 `95884a32` 的列表 DTO/Service 尚未体现修复，而新版 OpenAPI 已引用五字段 schema。需要取得修复版本或运行证据核验关联和组装。
- 尚未在目标环境验证目标接口、空对象/字段的实际序列化、数据样本及清理；不能把历史实现观察当作当前接口已通过。OpenAPI 3.1 的对象和字符串类型未包含 `null`，严格 schema 校验与已确认空值口径存在差异，详见接口分析。
