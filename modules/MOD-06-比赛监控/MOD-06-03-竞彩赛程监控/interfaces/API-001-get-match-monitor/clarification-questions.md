### Q-003 实测记录

2026-11-02 在授权的 `dev_newgoal` 测试环境执行测试点 78：竞彩赛程指向旧足球标准比赛 3594，旧比赛 `replace_id=3595`，新比赛 3595 存在且为足球。独立 SQL 预期 `sMatchId=3595`，接口实际返回 `sMatchId=null`；单条与全量运行均复现。测试记录已按主键清理。该结果与已确认口径不符，保留失败用例并请开发核查；不以实测覆盖用户确认。

本地 `SportteryMatchMonitorService.enrich` 使用 `findBySportIdAndReplaceIdIsNullAndMatchIdIn` 查询原关联 ID，静态代码路径可能解释该现象；尚未验证当前测试服务部署版本与本地源码完全一致，不能仅凭本地源码断定部署根因。

### Q-009 实测记录

2026-11-02 在授权的 `dev_newgoal` 测试环境执行测试点 87：足球标准比赛状态 1200（完场），贝泰比赛 870000101 存在 `closed`、`ended` 的 live 行。独立 SQL 能关联该行，接口返回 `beitaiFootballMatchLiveDTO=null`；单条与全量执行均复现。测试记录已清理。该结果与已确认的“完场仍返回已有 live 对象”不符，保留失败用例并请开发核查。

本地 `SportteryMatchMonitorService.enrich` 查询及组装 live 对象均有赛中状态限制，静态代码路径与现象一致；测试服务部署版本未核实，不据此断言其实际运行代码。

### Q-007 实测记录

2026-11-02 在授权的 `dev_newgoal` 测试环境执行测试点 91～99：按竞彩比赛和运动项目插入事件，不创建任务，六种颜色标题及时间、项目隔离场景返回 `rowColor=NONE`，与按标题返回颜色的已确认口径不符；无事件和非颜色事件的 90、100 通过。97～99 尚无法据此判断排序及跨项目颜色逻辑，因为基础颜色未正确返回，99 的断言在足球行先失败。测试记录已清理。

本地 `SportteryMatchMonitorRules` 的无任务路径使用 event code/identity data 而不是 `reason_title`，且事件排序使用创建时间；这一静态路径可能解释差异。由于测试服务部署版本未核实，需开发确认部署代码及修复，不将本地源码等同于当前部署事实。

2026-11-03 后续回归中，测试库当前竞彩事件表已无 `event_code` 字段，按当前表结构调整测试造数后，90～92、94～96、98～100 在完整执行中通过；93 在完整执行时出现会话被其他登录挤下线，独立重试通过。97 在完整执行和独立重试中均为预期 `YELLOW`、实际 `RED`，更新时间优先规则仍有差异。该观察不能证明其他尚未覆盖的颜色组合均正确，也不能证明测试服务部署版本与本地源码一致。
