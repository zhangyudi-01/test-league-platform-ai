# 竞彩赛程监控历史复用分析

## 目的

本目录记录旧“比赛赛程监控”测试资料对 MOD-06-03 的可复用经验、限制和不可沿用契约。它是历史参考，不是当前需求、API 契约或测试用例。

## 索引

| 文件 | 职责 |
|---|---|
| [match-monitoring-reuse-review.md](./match-monitoring-reuse-review.md) | 历史需求、API、SQL、脚本、fixture 和造数 helper 的逐项复用决策 |

## 权威边界

1. 当前行为以模块需求包及已确认的 `preanalysis/03-clarification-questions.md` 为需求依据。
2. 当前接口路径、参数和响应结构以当前 `data-backend-openapi.json` 及用户对缺失/差异的明确确认为依据；实现代码只用于核对实现行为和发现差异。
3. 数据表和数据所有权以当前第十三轮数据库设计及 DDL 为准。
4. 本目录中的 `/s-match`、`/s-match/live`、`s_event`、`task` 和旧赛果链路只作为历史实现/测试准备参考，不自动迁移到 Sporttery 竞彩接口。

## 阶段用法

- `module-requirement-preanalysis`：分析人员应显式读取本目录索引和复用回顾，把确实有帮助的已确认背景写入 Context Pack，并保留“历史参考”标注；不将历史资料改写为需求原文或新增 RSU。
- 接口分析：先读取复用回顾，再分别核对 `preanalysis/`、当前 OpenAPI、数据库设计/DDL 和当前实现。接口分析中的验收断言不能仅由旧脚本或旧接口决定；用户明确确认沿用的部分按确认口径处理。
- 用例/脚本：只复用被标注为“可复用”的测试组织、动态预期和清理模式；每个 helper 使用前仍须检查其实际写入表和运动项目范围。

## 维护规则

发现新历史资料时先登记具体文件和适用结论；不要将旧文件复制到本模块。若历史资料与当前契约冲突，记录冲突并以当前契约为准，不在本目录裁决新需求。
