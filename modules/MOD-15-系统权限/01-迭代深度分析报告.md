## 一、模块定位与 13 轮迭代背景

### 1.1 模块在系统中的位置与 RBAC 权限控制链路

【系统权限】是竞猜赛事运营系统实现**基于角色的访问控制（RBAC：账号 `toto_account` ↔ 角色 `toto_role` ↔ 权限 `toto_permission`）**的核心安全基座。

在系统中，权限控制贯穿**“管理端配置 → 登录态加载 → 前端路由/菜单/按钮渲染 → 后端接口鉴权拦截”**全链路：

```mermaid
flowchart TD
    subgraph 权限配置层 ["1. 角色权限配置 (用户管理 -> 角色管理)"]
        ADMIN["安全保密管理员<br>(role_id=1)"] -->|新建/修改角色| TREE["角色权限树 UI<br>(一级菜单 -> 二级菜单 -> 功能点)"]
        TREE -->|POST/PATCH /data-backend/role| RP[("toto_role_permission<br>角色-权限关联表")]
        PERM[("toto_permission<br>系统权限字典表 #1~#153")] -->|GET /access/permission| TREE
    end

    subgraph 权限生效与前端控制层 ["2. 登录生效与前端显隐控制"]
        USER["业务运营账号<br>(重新登录生效)"] -->|拉取角色权限集| FE["前端权限守卫"]
        FE -->|模块/二级菜单下未开启任何权限| HIDE_MENU["整个一级/二级菜单隐藏"]
        FE -->|已开启菜单下任一权限| SHOW_MENU["展示菜单并按三级权限控制页面内功能按钮显隐"]
    end

    subgraph 后端鉴权层 ["3. 后端服务接口鉴权"]
        SHOW_MENU -->|发起业务请求| BFF["data-bff / data-backend 权限拦截"]
        PERM -->|urls JSON (url + httpMethod)| BFF
    end
```

## 二、本次 13 轮冲刺 `✅` 需求逐条深度拆解

### 2.1 全局基础规则：菜单隐藏总则与权限生效机制

**需求原文**：
- **模块需求包功能说明**：`若模块、菜单未开启任何权限，整个菜单隐藏`
- **PBL-639 验收标准**：
  - `1、可正确配置竞彩赛程监控、竞彩赛事管理、竞彩球队管理、异常详情修改权限；`
  - `2、未开启上述权限时可正确隐藏对应功能。`
- **PRD 角色管理（修改角色规则 4 / 修改账号规则 4）**：`修改后的角色权限在用户重新登录后生效` / `账号修改后的权限在其重新登录后生效`。

**深度解读与层级判定规则**：
1. **一级菜单（模块级）显隐规则**：
   - 当某角色在某一级菜单（如 `比赛监控`、`异常管理`、`基础信息管理`）下的**所有二级菜单的所有功能点均未开启**时，左侧导航栏隐藏整个一级菜单；
   - 当角色在该一级菜单下**仅开启了本次 13 轮新增的二级菜单/功能点**（例如：在 `比赛监控` 下仅勾选了 `竞彩赛程监控-查询`，未勾选 `比赛赛程监控` 和 `赛果确认记录`），则一级菜单 `比赛监控` 正常显示，且展开后仅显示已授权的 `竞彩赛程监控` 二级菜单。
2. **二级菜单（菜单级）显隐规则**：
   - `竞彩赛程监控`：当 `查询` 与 `备注` 均未开启时，在 `比赛监控` 下隐藏 `竞彩赛程监控` 二级菜单；开启其中任一权限时，展示该二级菜单。
   - `竞彩赛事管理`：当 `查询` 与 `匹配` 均未开启时，在 `基础信息管理` 下隐藏 `竞彩赛事管理` 二级菜单；开启其中任一权限时，展示该二级菜单。
   - `竞彩球队管理`：当 `查询` 与 `匹配` 均未开启时，在 `基础信息管理` 下隐藏 `竞彩球队管理` 二级菜单；开启其中任一权限时，展示该二级菜单。
   - `告警管理`（含新增功能点的存量二级菜单）：当存量 `查询；核实；确认；备注` 与新增 `✅修改✅` 全部未开启时，隐藏 `告警管理` 二级菜单。
3. **三级功能点（按钮/操作级）显隐规则**：
   - 勾选对应三级功能点权限 → 页面展示对应操作入口并允许调用后端接口；
   - 未勾选对应三级功能点权限 → 页面隐藏对应操作入口（且后端拦截对应接口调用）。
4. **角色管理配置与生效闭环**：
   - 在【用户管理 -> 角色管理】的**添加角色**、**修改角色**、**角色详情**弹窗/页面中，权限树对应一级菜单下必须正确展示 `✅竞彩赛程监控✅（查询；备注）`、`告警管理（...；✅修改✅）`、`✅竞彩赛事管理✅（查询；匹配）`、`✅竞彩球队管理✅（查询；匹配）`；
   - 修改已有角色（勾选或取消勾选上述新增权限）并保存后，已登录的关联账号在刷新页面时仍维持旧权限，**退出并重新登录后**新权限正式生效。

## 四、测试点设计指引（核心测试面梳理）

围绕需求包中的 `✅` 标记内容与 PBL-639 验收标准，后续测试点将聚焦以下 **4 大核心测试面**：

1. **角色权限配置与回显（PBL-639 验收标准 1）**：
   - 在【用户管理 -> 角色管理】的新建角色、修改角色页面，权限树中可看到并勾选：
     - `比赛监控` -> `竞彩赛程监控` -> `查询`、`备注`
     - `异常管理` -> `告警管理` -> `修改`
     - `基础信息管理` -> `竞彩赛事管理` -> `查询`、`匹配`
     - `基础信息管理` -> `竞彩球队管理` -> `查询`、`匹配`
   - 保存后在【角色详情】与【修改角色】中正确回显已勾选的新增权限；
   - 修改已有角色的上述新增权限后，关联账号**重新登录**后权限变更生效。
2. **模块与菜单级显隐控制（需求包“若模块、菜单未开启任何权限，整个菜单隐藏”）**：
   - 未开启 `竞彩赛程监控` 下任何权限（查询、备注均未勾选）时，隐藏 `竞彩赛程监控` 二级菜单；开启任一权限时展示；
   - 未开启 `竞彩赛事管理` 下任何权限（查询、匹配均未勾选）时，隐藏 `竞彩赛事管理` 二级菜单；开启任一权限时展示；
   - 未开启 `竞彩球队管理` 下任何权限（查询、匹配均未勾选）时，隐藏 `竞彩球队管理` 二级菜单；开启任一权限时展示；
   - 当 `比赛监控` / `基础信息管理` / `异常管理` 一级菜单下的所有二级菜单均未开启任何权限时，整个一级菜单隐藏；若仅开启了本次新增权限（如仅开启 `竞彩赛程监控-查询`），则对应一级菜单正常显示。
3. **新增功能点（页面操作级）显隐控制（PBL-639 验收标准 2）**：
   - **竞彩赛程监控**：开启 `查询` + `备注` 时可使用查询与备注功能；仅开启 `查询`、未开启 `备注` 时，可正常查询竞彩赛程监控列表，但隐藏备注操作功能；
   - **告警管理-修改**：开启 `查询` + `修改` 时，告警列表中已确认/已解除状态的记录显示【修改】按钮并可修改异常详情；仅开启 `查询`（或核实/确认/备注）、未开启 `修改` 时，告警列表隐藏【修改】按钮；
   - **竞彩赛事管理**：开启 `查询` + `匹配` 时可查询列表并进行赛事匹配；仅开启 `查询`、未开启 `匹配` 时，可查询竞彩赛事列表，但隐藏【匹配】功能；
   - **竞彩球队管理**：开启 `查询` + `匹配` 时可查询列表并进行球队匹配；仅开启 `查询`、未开启 `匹配` 时，可查询竞彩球队列表，但隐藏【匹配】功能。

```sql
-- 1. 核验系统权限表中第 13 轮新增的 7 个权限节点（#147~#153）
SELECT 
    permission_id,
    permission_type,
    level1,
    level1_name,
    level2,
    level2_name,
    level3,
    level3_name,
    is_deleted,
    urls

WHERE permission_id IN (147, 148, 149, 150, 151, 152, 153)
   OR level2_name IN ('竞彩赛事管理', '竞彩球队管理', '竞彩赛程监控')
   OR (level2_name = '告警管理' AND level3_name = '修改')
ORDER BY permission_id;

-- 2. 查询指定角色（如 role_id=11 全权限用户 或测试角色）已绑定的 13 轮新增权限
SELECT 
    rp.role_permission_id,
    r.role_id,
    r.role_name,
    p.permission_id,
    p.level1_name,
    p.level2_name,
    p.level3_name,
    p.level3
FROM toto_role_permission rp
JOIN toto_role r ON rp.role_id = r.role_id
JOIN toto_permission p ON rp.permission_id = p.permission_id
WHERE p.permission_id IN (147, 148, 149, 150, 151, 152, 153)
ORDER BY r.role_id, p.permission_id;

-- 3. 查询测试账号当前绑定的角色及其状态
SELECT 
    a.account_id,
    a.account,
    a.account_user,
    a.account_status,
    r.role_id,
    r.role_name,
    r.is_deleted AS role_deleted
FROM toto_account a
JOIN toto_account_role ar ON a.account_id = ar.account_id
JOIN toto_role r ON ar.role_id = r.role_id
WHERE a.is_deleted = 0
ORDER BY a.account_id DESC
LIMIT 20;
```
