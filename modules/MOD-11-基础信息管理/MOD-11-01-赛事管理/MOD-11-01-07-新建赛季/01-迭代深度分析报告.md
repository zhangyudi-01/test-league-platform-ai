## 一、本次迭代变更背景与真实交互机制

### 1.1 业务前世今生与机制拆解

在赛事运营系统的前端页面流转中，新建赛季与赛季匹配之间存在一条连续的工作流：

```
【新建赛季页面】(图1)
  填写赛季年、赛季名称等信息
  点击【创建并继续】保存入库
       ↓ (页面跳转，并携带"新建来源标识"，如 router state/query: from=create)
【匹配赛季页面】(图2)
  展示当前赛季基本信息、贝泰/纳米候选赛季列表
  勾选候选赛季，点击【匹配】
       ↓
  弹出二次确认弹窗，用户点击【确认】
       ↓ (调用 POST 匹配接口成功)
  ┌──────────────────────────────────────────────────────────────┐
  │ 旧版逻辑：                                                    │
  │   前端检测到带有"新建来源标识"                                │
  │   → 强制路由跳转至该赛季的【关联球队】页面                      │
  │                                                              │
  │   （注：若用户在图2点击【返回】退回赛季详情，清除新建标识；   │
  │     再重新打开匹配页进行匹配，原本就不会跳转至关联球队页）     │
  └──────────────────────────────────────────────────────────────┘
       ↓
  ┌──────────────────────────────────────────────────────────────┐
  │ ✅ 本次（13轮）迭代调整核心（PBL-636）：                       │
  │   即使带着"新建来源标识"，在匹配赛季确认成功后：              │
  │   → 也【绝对不再跳转】至关联球队页面！                        │
  │   → 统一【刷新并停留在当前匹配页面】！                        │
  └──────────────────────────────────────────────────────────────┘
```

### 1.2 关键事实澄清与边界说明

1. **【匹配】按钮文案非本次变更**：
   - 从实际系统截图（图2）可见，右下角操作按钮在上一轮迭代中已正式定名为【**匹配**】（原【匹配并继续】已在上轮废弃）。
   - **本次无需验证按钮名称变更**，重点纯粹在**点击【匹配】确认后的路由流转拦截与页面停留**。
2. **纯前端交互调整，无数据库及接口变更**：
   - 本次 PBL-636 的改造点 100% 发生在**前端路由跳转控制器与匹配成功后的回调逻辑**（去除跳转 `/r-season-team` 的分支逻辑，统一执行当前页数据 reload）。
   - 后端数据持久化接口（`POST /data-backend/dimension/relations/season`）及底层数据库表结构、数据逻辑无任何调整，**无需编写及执行 SQL 核验脚本**。
3. **测试核心聚焦面**：
   - 核心正向链路：从新建赛季页点击【创建并继续】进入匹配页（携带新建标识），完成匹配确认后，页面原地刷新停留，严禁跳转关联球队页面。
   - 对照回归链路：从新建进入匹配页后点击【返回】退出（清除新建标识），再从详情重新进入匹配，匹配后同样正常原地刷新停留。
   - 原地停留后的状态完整性：刚刚匹配的赛季状态更新为“已匹配”，复选框置灰锁定不可取消，头部数据源标签实时联动，【匹配】按钮自动置灰防重。

## 二、本次迭代核心变更对照矩阵

| 场景链路 | 旧版流转表现 | 13 轮冲刺变更（✅ PBL-636） | 核心验证关注点 |
|---|---|---|---|
| **链路 A：新建赛季刚进入匹配页（携带新建标识）** | 勾选赛季点击【匹配】并确认后，系统根据新建标识**强制自动跳转至关联球队页面** | ✅ **不再跳转至关联球队页面，页面正确刷新并停留在当前页面（当前赛季的匹配页）** | **绝对红线项**：拦截路由跳转，确认页面留在 `/season-match` 路径 |
| **链路 B：退出后再进匹配页（无新建标识）** | 正常原地刷新并停留在当前页面 | 保持一致：原地刷新并停留在当前页面 | 确保原有非新建链路的正常停留机制未受连带破坏 |
| **停留后状态刷新** | 链路 A 直接跳走无停留表现 | ✅ 勾选行状态刷新为“已匹配”，复选框置灰锁定不可取消；头部数据源标签更新为“已匹配”；【匹配】按钮恢复置灰禁用 | 页面数据就地重载与按钮防并发防重提交 |
| **二次确认弹窗交互** | 弹出二次确认提示，点击【取消】关闭弹窗 | 保持一致：点击【取消】不触发请求，维持在匹配页面当前状态 | 防误触安全性 |

## 三、测试用例设计策略与准则

根据《必读-需求包标记符号说明.md》及用户实地指导：
1. **零冗余原则**：完全剔除表单录入常规限制等存量历史内容，严禁在增量测试集中引入无关回归点。
2. **场景对比闭环**：通过“新建直接匹配” vs “新建后退出再进匹配”构筑完整路由标识覆盖。
3. **真实交互断言**：围绕弹窗确认、轻提示“匹配成功”、URL 路径无跳转、页面就地数据刷新与组件锁定展开断言。
