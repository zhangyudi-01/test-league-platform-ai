# 需求文档版本管理规则（必读）

> 适用范围：`global/source-materials/current-requirement/`（当前生效需求）与 `global/source-materials/history-requirements/`（历史归档需求）的文档管理。
> 背景：PRD 等需求文档会随迭代持续修订（如《竞猜赛事运营系统需求PRD文档》已从 V0.1 迭代至 V0.6）。本文规定新版本到来时的归档动作，保证任何时点的分析产出都能追溯到其依据的需求版本。

---

## 一、核心规则：替换 + 归档，两步走

PRD 更新后**不是简单覆盖，也不是并存多版**，标准动作两步：

### 第 1 步：归档旧版（先做）

将 `current-requirement/` 下的旧版文档（含其引用的附件，如本次有变动）**移动**到 `history-requirements/`，按以下命名规范：

```
history-requirements/
└── <文档名>-V<版本号>.md            ← 文件名追加版本号后缀
   例：竞猜赛事运营系统需求PRD文档-V0.6.md
```

- 版本号取文档内"修订记录"表的**最后一行版本号**；
- 附件（attachments/）如同时更新，旧附件一并归档到同名子目录：`attachments-V<版本号>/`；附件未变则不移，新版继续引用；
- 归档是**移动**而非复制，`current-requirement/` 下同一文档始终只有一份。

### 第 2 步：放入新版

将最新版 PRD 放入 `current-requirement/`，**保持原文件名不变**（不带版本号）——所有既有引用路径（分析报告、测试点中的"详见 PRD 通用需求"等）无需修改即可指向最新版。

```
current-requirement/
├── 竞猜赛事运营系统需求PRD文档.md    ← 永远是最新版，文件名固定
└── attachments/                     ← 最新版引用的附件
```

## 二、配套动作（更新后必做）

1. **核对版本号**：打开新版"修订记录"表，确认新增了修订行（版本号、日期、修订描述）——这是后续判断"需求又改了什么"的第一入口；
2. **识别增量**：对照修订记录的修订描述定位变更章节；若修订描述为空，用归档的旧版做**全文 diff**（VSCode/IDEA 比较两个文件）找出差异段落；
3. **更新标记符号**：如需求方在新版中用 ✅/⭐ 框选了变更（见《必读-需求包标记符号说明.md》），按符号流程处理；如未框选，以 diff 结果为准并主动向需求方确认变更点；
4. **产出物影响评估**：检查基于旧版产出的分析报告/测试点是否引用了被修改的章节——受影响的断言按《必读-测试点编写规范.md》更新（作废断言划线保留，不静默删除）；
5. **在产出物中记录依据版本**：分析报告头部"信息源"处标注所依据的 PRD 版本号（如"《竞猜赛事运营系统需求PRD文档》V0.6"），实现版本可追溯。

## 三、判断速查

| 场景 | 处理 |
| --- | --- |
| PRD 小修（文字/格式，无规则变化） | 照常归档替换；产出物不动 |
| PRD 修改了规则但与我模块无关 | 归档替换；仅检查全局文档（架构报告/ER 图）是否需更新 |
| PRD 修改了我模块依赖的规则 | 归档替换 + 评估产出物影响 + 更新断言 + 记录依据版本 |
| 拿到的"新版"没有修订记录增量 | 先 diff 确认实际变更，必要时向需求方要变更说明，再归档替换 |
| 模块需求包（00-module-requirement-pack.md）更新 | 不归档（它是迭代工作件），直接在原文件上更新，变更用 ⭐ 标记区分层次 |

## 四、目录职责总览

```
global/source-materials/
├── current-requirement/      当前生效的需求文档（每份文档只保留最新版）
│   └── attachments/          当前版引用的附件
├── history-requirements/     历史归档（文件名带版本号，按需 diff 追溯）
├── api-docs/                 接口设计（OpenAPI 等，随迭代同样适用归档规则）
├── database-docs/            数据库设计（同上）
├── analysis-docs/            全局分析产出（架构/ER/追溯矩阵）
├── test-cases/               测试用例模板
├── test-case-points/         （预留）测试点相关
├── 必读-测试点编写规范.md
├── 必读-需求包标记符号说明.md
└── 必读-需求文档版本管理规则.md   ← 本文
```
