### 测试内容

| 序号 | 测试项 | 测试点 | 备注 |
| --- | --- | --- | --- |
| 1 | 获取球队-展示 | **【空值精准识别与显空】** 校验获取的球队在底层 `m_team` 缺失北单全称、简称，或**仅缺失其中一项**时，前端对应缺失的列是否严格**显示为空**。 | sql验证 |
| 2 | 用户确认-拦截校验 | **【未补全强拦截】** 针对带有空值的球队，用户**不填补**直接点击【关联】并【确认】。校验系统成功阻断入库，强提示全称/简称不能为空。 |  |
| 3 | 用户确认-拦截校验 | **【超长及当前赛季重名拦截】** 针对空值球队，用户填补名字超长（**全称>20，简称>16**），或填补的名称与**当前赛季已有的其他球队重名**。校验点击【确认】时系统能否准确弹窗拦截。 |  |
| 4 | 用户确认-业务规则 | **【全局重名时的“静默跳过”与“连坐机制”**】 针对空值球队，填补的名称未与本赛季重名，但与**系统内其他赛季/其他球队**重名。校验点击【确认】时，系统不报错、不弹窗，提示关联成功；但底层 `m_team` 表**不执行更新**（遵循一假全假的连坐跳过规则）。 |  |
| 5 | 用户确认-逻辑查重 | **【自身重名误伤放行】** 针对仅一项为空的球队，用户补全空项，**保持原本有值的项不变**。校验系统顺利关联，且底层 `m_team` 成功更新（**验证查重时精准排除了当前球队自身**）。 |  |
| 6 | 用户确认-覆盖更新 | **【存在空值时的全量反写更新】** 针对有空值的球队（无论是双空还是单空），用户填补空项或**同时修改了原本有值的项**并确认。校验关联成功的同时，底层 `m_team` 是否将两个新值**全量覆盖更新**。 |  |
| 7 | 用户确认-防篡改 | **【双非空时的底表防篡改】** 若获取的球队**双名称原本均有值**，用户在前端强制修改并确认关联。校验系统仅保存当前赛季映射（`r_season_team`），**绝对不触发**底层 `m_team` 的 UPDATE 操作。 |  |
| 8 | 技术边界-空字符容错 | **【**`**NULL**` **与空字符串** `**""**` **的等效识别】** 模拟底层表对应字段为**空字符串** `**""**`（而非 `NULL`）。校验系统能否正确识别为“空”，前端显空并成功触发覆盖更新逻辑。 | 防后端只校验 `IS NULL` 导致的漏测。 |
| 9 | 技术边界-字符严格校验 | **【首尾空格拦截与大小写区分】** 校验前端是否限制首尾输入空格；校验后台查重是否遵循 `utf8mb4_bin` 规则严格区分大小写（如 `acmilan` 与 `ACMilan` 视为不重名，可更新入库）。 | 字符集匹配与Trim清洗测试。 |
| 10 | 技术边界-极限并发 | **【并发触发底表 1062 异常的捕获降级】** 模拟高并发下两人同时提交相同名称。校验即便触发数据库底层唯一索引异常，系统也能 Catch 并降级为\*\*“静默跳过”\*\*，严禁页面崩溃。 | 极端场景下代码鲁棒性测试。 |
