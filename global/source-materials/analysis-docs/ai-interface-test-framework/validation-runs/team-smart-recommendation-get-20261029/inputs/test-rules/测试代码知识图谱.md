## 3. 核心架构

### 3.1 执行流程总览

```
pytest 运行
  │
  ├─ 顶层 conftest.py
  │   init_db (session,autouse) → clear_table_snapshot()
  │
  ├─ 套件级 conftest.py
  │   创建 session 级 API 客户端 fixture
  │
  └─ test 函数
      │
      ├─ @parametrize(case_dict ← api_test_data(Excel))
      │
      └─ api_client.test(case_dict, generator)
          │
          ├─ 1. 登录控制（case_dict['是否登录']）
          ├─ 2. generator 前置（yield 前 → next()）
          ├─ 3. 参数 → JSON 转换
          ├─ 4. request() 发送 HTTP + allure 记录
          ├─ 5. verify_response() 预期对比（json_tools.diff）
          └─ 6. generator 后置（yield 后 → next()）
                  → DB 验证 + 数据清理
```

## 4. 核心框架类详解

### 4.1 `common/api.py` — API 基类

| 方法 | 职责 |
|---|---|
| `test(case_dict, generator)` | 数据驱动入口：登录控制 → generator 前置 → 参数转换 → request() |
| `request(case_dict, generator)` | 发送 HTTP + allure 记录 → 响应验证 → generator 后置 |
| `verify_response(resp, case_dict)` | 用 `json_tools.diff` 深度对比预期与实际 |
| `login()` | 登录（子类重写，基类空实现） |
| `success_response` | 成功判定模板 `{'code': 0}` |

**`test()` 流程**：
1. 检查 `case_dict['是否登录']` → 未登录则 `self.login()`
2. generator 存在 → `next(generator)` 执行前置
3. `case_dict['参数']` → JSON 解析；`case_dict['处理数据']` → `eval()` 执行
4. `request()` 发送 HTTP 请求 + allure 记录
5. `verify_response()` 预期对比
6. generator 存在 → `next(generator)` 执行后置（DB 验证 + 清理）

### 4.2 `common/data.py` — 数据层核心

#### DB 类 — MySQL 封装

| 方法 | 用途 |
|---|---|
| `get_asdict(table, query)` | 查询单行→字典 |
| `get_aslist(table, query)` | 查询多行→字典列表 |
| `execute(sql, params)` | 执行原生 SQL |
| `update(table, data, query)` | 更新 |
| `replace_into(table, data)` | REPLACE INTO |
| `insert(table, data)` | 插入 |
| `delete(table, query)` | 删除 |
| `count(table, query)` | 计数 |
| `backup_to_table(table)` | 备份到 `_backup` 表 |
| `recovery_from_table(table)` | 从备份恢复 |
| `snapshot(tables)` | 多表快照 |
| `clear_table_snapshot()` | 清理快照残留 |

**`_sql_where()` WHERE 构造器后缀**：

| 后缀 | 操作符 | 后缀 | 操作符 |
|---|---|---|---|

| `__isnull` | `IS [NOT] NULL` | `__not` | `!=` |

| 后缀 | 转换 | 后缀 | 转换 |
|---|---|---|---|
| `\|json` | `json.loads()` | `\|float` | `float()` |
| `\|list` | 逗号分割→list | `\|time` | datetime |
| `\|int` | `int()` | `\|list\|int` | list→int |

#### CaseDict 结构

```python
class CaseDict(TypedDict):
    接口名: str          # 接口名称
    路径: str            # API 路径
    测试内容: str        # 用例描述
    处理数据: str        # generator 函数名（eval 执行）

    是否登录: str        # "是"/"否"

```

#### api_test_data() — Excel→CaseDict 读取流程

```

```

## 5. Generator 前后置模式

### 核心理念

Generator 函数以 `yield` 为界，实现三阶段测试：

```
yield 之前 → next()    前置：准备数据
yield      → 框架      执行：HTTP 请求 + 响应验证
yield 之后 → next()    后置：DB 验证 + 数据清理
```

### 标准模板

```python
from common.data import DB_CONN, CaseDict

def assert_xxx(case_dict: CaseDict):
    # ===== 前置（yield 之前）=====
    # 准备测试数据（可选）
    yield  # ← 框架在此处发送请求并验证响应

    # ===== 后置（yield 之后）=====
    if case_dict['预期']['code'] == 0:
        # 成功用例：验证 DB 副作用
        count = DB_CONN.count('m_team', {'name': 'xxx'})
        assert count == 1
    # 数据清理
    DB_CONN.delete('m_team', {'name': 'xxx'})


@pytest.mark.parametrize('case_dict', api_test_data(Path(__file__).parent / 'test_xxx.xlsx'))
def test_xxx(api_client: SomeApi, case_dict: CaseDict):
    api_client.test(case_dict, eval(case_dict['处理数据'] or 'None'))
```

## 8. OpenAPI 测试套件

### 与其他套件的根本差异

- **无 Session**：每请求独立 HMAC-SHA256 签名，三元组头 `X-OpenAPI-User` / `X-OpenAPI-Time` / `X-OpenAPI-Sign`
- **重写 request()**：OpenApi 类重写父类 request() 注入签名头
- **raw_get()**：绕过 test() 流程直接请求，用于负向测试
- **set_auth_override()**：注入错误的签名/时间戳/用户，测试认证失败场景

### Session 级 Setup

```python
# openapi/conftest.py
# 创建 3 个测试用户 → 授权 8 个业务路径 → 配置限流策略
# 提供 fixture：
#   openapi       — 有权用户
#   openapi_rl    — 限流测试用户
#   openapi_noperm — 无权限用户
#   audit_asserter — AuditRecordAsserter
#   openapi_redis  — Redis 连接
# autouse:
#   clean_redis_keys — 每用例清理限流缓存
#   reset_auth       — 每用例重置认证状态
```

### 子目录结构

| 子目录 | 文件数 | 说明 |
|---|---|---|
| auth/ | 1 | HMAC 签名 5 类场景（正常/缺头/错签/过期/用户不存在） |
| ratelimit/ | 1 | COOLDOWN 触发、Retry-After、批次旁路、指纹限流 |
| permission/ | 1 | 有权放行 / 无权拒绝 |
| audit/ | 5 | SUCCESS/AUTH_FAIL/PERMISSION_FAIL/RATE_LIMIT_FAIL/SERVICE_EXCEPTION |
| business/ | 9 | 8 个业务接口功能测试 |

### HMAC-SHA256 签名机制 (`common/openapi_sign.py`)

```
签名计算流程：
1. 合并请求参数 (query + body)
2. 参数按 ASCII 排序拼接
3. HMAC key = SHA-256(secret) hex
4. HMAC-SHA256(key, user_code + timestamp + sorted_params)
5. 输出 hex 摘要 → X-OpenAPI-Sign

请求头三元组：
  X-OpenAPI-User: 用户编码
  X-OpenAPI-Time: 时间戳
  X-OpenAPI-Sign: 签名摘要
```

### 审计日志验证 (`common/openapi_audit_helper.py`)

```
AuditRecordAsserter
├─ wait_and_find()         轮询异步落库（5s 超时，0.5s 间隔）
├─ assert_common_fields()  13 列通用字段断言
├─ assert_event_fields()   6 列事件差异化断言
└─ assert_full_record()    一站式全 19 列断言

5 类事件类型：
  SUCCESS / AUTH_FAIL / PERMISSION_FAIL / RATE_LIMIT_FAIL / SERVICE_EXCEPTION
```

### 限流测试

- COOLDOWN 策略：触发后返回 HTTP 429 + `Retry-After` 头
- 指纹批次旁路：不同请求指纹不受同一限流窗口影响
- 每用例通过 `clean_redis_keys` fixture 清理限流缓存
