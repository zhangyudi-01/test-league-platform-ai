## 1. 总则

### 1.1 两种测试模式并存

| 模式 | 适用场景 | 特点 |
|------|----------|------|
| **Excel 驱动模式** | 大批量接口回归、参数化用例多、需数据预处理/还原 | 用例与代码分离，非技术人员可维护 Excel |
| **纯 Python 模式** | 精细场景验证、鉴权/限流/审计等需精确控制 HTTP 头 | 代码即用例，灵活度高 |

**选择原则**：同一接口 5 条以上用例优先 Excel 驱动；涉及 HTTP 头级别控制用纯 Python。两种模式可在同一套件并存。

### 1.2 核心依赖

```python

from common.data import api_test_data   # Excel → CaseDict 列表
```

## 3. API 接口类编写规范

### 3.1 标准 session 接口类

继承 `API`，定义 `base_url`/`name`/`success_response`，按需覆写 `login()`/`logout()`。

**✅ 正例**（参考 `apis/_data_bff.py`）：
```python
from common.api import API, ApiError
from common.data import DB_CONN
from settings import DATA_BFF_URL

class DataBff(API):
    base_url = f'{DATA_BFF_URL}/api'
    name = '管理端接口'
    success_response = {'code': 0}

    def login(self, username='test3', password='Vegas2.0'):
        response = self.request('/login', 'POST', 300, {
            "username": username, "password": password, 'code': code
        }, content_type='multipart/form-data').json()
        assert response['code'] == 0, f'登录失败：{response}'

    def logout(self):
        response = self.request('/logout', 'POST', {}).json()
        assert response['code'] == 0, '登出失败'
```

### 3.2 无 session 接口类（重写 request）

**✅ 正例**（参考 `apis/_openapi.py`）：
```python
class OpenApi(API):
    success_response = {'code': 0}

    def __init__(self, base_url=None, user_code=None, secret=None):
        super().__init__(name='OpenAPI', base_url=base_url or OPENAPI_URL)
        self.user_code = user_code or OPENAPI_TEST_USER
        self.secret = secret or OPENAPI_TEST_SECRET

    def login(self, username='', password=''):
        pass  # 空操作 — 无 session

    def request(self, route, method, time_out=300, request_param={},
                expect_result=None, generator=None,
                content_type=None, expect_http_code=None):
        """重写 request：注入 HMAC 签名头"""
        auth_headers = self._compute_auth_headers(request_param)
        old_options = dict(self.options)
        self.options['headers'] = {**old_options.get('headers', {}), **auth_headers}
        try:
            return super().request(route, method, time_out, request_param,
                                   expect_result, generator, content_type, expect_http_code)
        finally:
            self.options = old_options

    def raw_get(self, route, params=None, headers=None):
        """绕过 test/request 流程，返回原始 Response"""
        url = self.base_url + route
        if headers is None:
            headers = self._compute_auth_headers(params)
        return self.session.get(url, params=params, headers=headers, timeout=300)
```

### 3.3 关键规则

1. **`base_url` 必须来自 `settings.py`**，不硬编码。
2. **新增 API 类必须在 `apis/__init__.py` 添加导出**：`from ._xxx import *`。
3. **session 认证**覆写 `login()`/`logout()`；**签名认证**覆写 `request()`。
4. **`raw_get`/`raw_post`** 用于需精确控制 HTTP 头或需原始 `Response` 的场景。

**❌ 反例**：
```python
class MyApi(API):
    base_url = 'http://192.168.22.218:30023/api'  # 硬编码，应从 settings 获取
```

## 5. conftest.py 与 fixture 编写规范

### 5.1 四层分层

| 层级 | 位置 | 作用域 | 典型用途 |
|------|------|--------|----------|
| 根级 | `conftest.py` | session/function | 全局 autouse：清理快照表、记录执行时间 |
| 服务级 | `testsuites/xxx/conftest.py` | session | API 实例 fixture |
| 功能级 | `testsuites/xxx/yyy/conftest.py` | session | 数据准备/清理 |
| 用例级 | test 文件内 | function | 单条用例前后置 |

### 5.2 根级 conftest

**✅ 正例**（参考 `conftest.py`）：
```python
@pytest.fixture(scope='function', autouse=True)
def print_time():
    allure.dynamic.parameter('执行时间', f'{datetime.now():%Y-%m-%d %H:%M:%S}')

@pytest.fixture(scope='session', autouse=True)
def init_db():
    clear_table_snapshot()
```

### 5.3 服务级 conftest — API 实例

**✅ 正例**（参考 `testsuites/data-bff/conftest.py`）：
```python
from apis import DataBff

@pytest.fixture(scope='session')
def data_bff():
    return DataBff()
```

### 5.4 session 级 DB setup/teardown

**✅ 正例**（参考 `testsuites/openapi/conftest.py`）：
```python
@pytest.fixture(scope='session', autouse=True)
def openapi_db_setup():
    # --- setup ---
    DB_CONN.execute("REPLACE INTO openapi_user ...", [...])
    yield {'main_uid': main_uid}
    # --- teardown ---
    DB_CONN.execute("DELETE FROM openapi_user WHERE ...", [...])
```

### 5.5 用例级 fixture

**✅ 正例**（参考 `testsuites/openapi/conftest.py` 中 `clean_redis_keys`）：
```python
@pytest.fixture
def clean_redis_keys(openapi_redis):
    """每个测试前后清理限流 Redis key"""
    def _clean():
        for key in openapi_redis.client.scan_iter(f'openapi:cooldown:{TEST_RL_USER}:*'):
            openapi_redis.client.delete(key)
    _clean()
    yield
    _clean()
```

### 5.6 共享常量放 `constants.py`

> **重要**：`conftest.py` 不能被 `import` 引用。共享常量必须放独立 `.py` 文件。

**✅ 正例**（参考 `testsuites/openapi/constants.py`）：
```python
# testsuites/openapi/constants.py
BUSINESS_PATHS = {
    'competition_list': '/openapi/v1/football/competition/list',
}
TEST_USER = 'test-openapi-001'
```
```python
# 在 test 文件中引用
from testsuites.openapi.constants import BUSINESS_PATHS
PATH = BUSINESS_PATHS['competition_list']
```

### 5.7 规则

- **scope**：API 实例和全局数据用 `session`；单用例清理用 `function`。
- **autouse**：仅用于全局必须的前后置，不在功能级滥用。
- **teardown 必须可靠**：yield 后的清理逻辑必须即使 setup 异常也能执行。

## 6. Excel 测试数据编写规范

### 6.1 Sheet 结构

| Sheet 名称 | 作用 | 必需 |
|------------|------|------|
| `接口路径` | 接口基本信息（接口名、路径、请求方式） | ✅ |
| `{接口名}` | 用例列表 | ✅ |
| `{接口名}-参数` | 每行一条用例的请求参数 | 可选 |
| `{接口名}-预期` | 每行一条用例的预期结果 | 可选 |

### 6.2 用例 Sheet 列说明

| 列名 | 说明 |
|------|------|
| `测试内容` | 用例描述（显示在 allure title） |
| `处理数据` | generator 函数名（如 `get_competition_list`），留空则无预处理 |
| `是否登录` | `是`=登录、`否`=登出、留空=默认登录 |
| `用户名`/`密码` | 可选，指定登录用户 |
| `HTTP_STATUS_CODE` | 可选，预期 HTTP 状态码，默认 200 |
| `描述` | 可选，显示在 allure description |
| `跳过` | 可选，填写原因则 `pytest.skip` |

### 6.3 `列名|类型` 语法

| 写法 | 含义 | 单元格值 → 转换结果 |
|------|------|---------------------|
| `参数\|json` | JSON 对象 | `{"page": 1}` → `{"page": 1}` |
| `id\|int` | 整数 | `42` → `42` |
| `ids\|list` | 列表 | `1,2,3` → `['1','2','3']` |
| `ids\|list\|int` | 整数列表 | `1,2,3` → `[1,2,3]` |
| `date\|time` | 时间 | `2024/01/01` → `'2024-01-01'` |
| 列名（无后缀） | 默认 str | `hello` → `'hello'` |

### 6.4 空行规则

整行为空时**自动停止读取**，用例之间不能留空行。

### 6.5 文件存放

```
data/{service-name}/接口测试用例_{业务名称}.xlsx
```

**✅ 正例**：`data/data-bff/接口测试用例_查询赛事列表.xlsx`  
**❌ 反例**：`data/赛事.xlsx`（缺少服务子目录和统一前缀）

## 8. Generator 模式规范

### 8.1 执行流程

```
api.test() 调用 next(generator)
    ↓
yield 前的代码 → 【前置：数据准备】
    ↓
yield → 挂起，等待 API 请求完成
    ↓
api.test() 调用 generator.send(actual_result)
    ↓
yield 后的代码 → 【后置：验证 + 还原】
```

### 8.2 标准写法

**✅ 正例 — 前置构造预期数据**（参考 `get_competition_list`）：
```python
def get_competition_list(case_dict: CaseDict):
    # ---- 前置：从 DB 查询预期结果 ----
    if case_dict['预期']['code'] == 0:
        sql_R = DB_CONN.get_asdict("SELECT ... FROM m_competition ...")
        case_dict['预期']['data'] = sql_R
        case_dict['预期']['meta']['totalElements'] = total

    yield  # 交出控制权

    # ---- 后置：（此例为空） ----
```

**✅ 正例 — 前置+后置验证+还原**（参考 `get_add_beitai`）：
```python
def get_add_beitai(case_dict: CaseDict):
    # ---- 前置：新增赛季数据 ----
    new_season_id = int(max_season_id) + 1
    DB_CONN.replace_into('beitai_football_season', new_season_info)
    DB_CONN.execute(f"delete from s_event where event_id = '...'")

    yield

    # ---- 后置：验证 + 还原 ----
    try:
        event_new = DB_CONN.get_asdict(
            f"SELECT * FROM s_event WHERE source_id = {source_id} LIMIT 1")
        for f in ['create_account', 'update_account', 'create_time', 'update_time']:
            del event_new[0][f]
        diff_list = diff(event_new[0], events_tmp)
        assert diff_list == [], f'差异：{json_dumps(diff_list)}'
    finally:
        # 无论断言是否通过都还原
        DB_CONN.delete('beitai_football_season', {'season_year': season_year})
        DB_CONN.delete('s_event', {'source_id': source_id})
```

### 8.3 关键规则

1. **yield 前=前置，yield 后=后置**——不可违反。
2. **后置还原必须用 `try...finally`**——保证断言失败时数据仍被清理。
3. **Generator 函数名与 Excel `处理数据` 列对应**。
4. **Generator 接收 `case_dict` 参数**——这是与 Excel 数据交互的唯一通道。

**❌ 反例**：还原代码在 assert 之后，断言失败则不执行。
**✅ 正例**：还原代码在 `finally` 块中。

## 9. DB / Redis 使用规范

### 9.1 DB 常用方法

```python
from common.data import DB_CONN

# 查询 list[dict]
rows = DB_CONN.get_asdict("SELECT * FROM m_team WHERE sport_id = %s", [1])

# 查询单值
count = DB_CONN.get_one("SELECT count(*) FROM m_team WHERE sport_id = %s", [1])

# 增删改
DB_CONN.insert('m_team', {'name_zh': '北京队', 'sport_id': 1})
DB_CONN.update('m_team', {'name_zh': '北京国安'}, {'team_id': 1})
DB_CONN.delete('m_team', {'team_id': 1})
```

### 9.2 query_dict 条件语法

```python
# 等于（默认）
DB_CONN.count('m_team', {'sport_id': 1})

# contains / startswith / endswith
DB_CONN.count('m_team', {'name_zh__contains': '北京'})

# gt / lt / gte / lte
DB_CONN.count('m_match', {'match_date__gt': '2024-01-01'})

# in（value 为 list）
DB_CONN.delete('m_team', {'team_id': [1, 2, 3]})

# between（value 为 2 元素 list）
DB_CONN.count('m_match', {'match_date__between': ['2024-01-01', '2024-12-31']})

# not（不等于 / not in）
DB_CONN.count('m_team', {'sport_id__not': 2})

# isnull
DB_CONN.count('m_team', {'name_en__isnull': True})
```

### 9.3 SQL 参数化

**✅ 正例**：`DB_CONN.get_asdict("... WHERE id = %s", [team_id])`  
**❌ 反例**：`DB_CONN.get_asdict(f"... WHERE id = {team_id}")`（注入风险）

## 10. 数据隔离与清理规范

### 10.1 三层清理机制

| 机制 | 方法 | 适用场景 |
|------|------|----------|
| 表级备份恢复 | `backup_to_table()` / `recovery_from_table()` | 修改了整表数据 |
| 行级快照 | `snapshot()` → `__snapshot` 表 | 修改了部分行 |
| 手动 CRUD | `insert` / `update` / `delete` | 精确控制少量数据 |

### 10.2 备份/恢复

```python
# 测试前备份
DB_CONN.backup_to_table('m_team', query_dict={'sport_id': 1})
# 执行测试...
# 测试后恢复
DB_CONN.recovery_from_table('m_team', query_dict={'sport_id': 1})
```

### 10.3 快照

```python
# 记录快照
DB_CONN.snapshot('m_match', {'match_date': '2024-01-01'})
# 执行测试...
# 通过比对快照表确认数据变化
```

### 10.4 规则

1. **测试数据必须有清理机制**，不能残留脏数据。
2. **测试用户独立**：不同测试套件使用不同 user_code，避免互相干扰。
3. **Redis key 带测试前缀**：如 `openapi:cooldown:test-openapi-rl-001:*`。
4. **session 级 setup/teardown 保证清理**：teardown 中无条件删除测试数据。
5. **Generator 的 `finally` 块保证 DB 还原**。

**✅ 正例 — session 级完整清理**（参考 `testsuites/openapi/conftest.py`）：
```python
@pytest.fixture(scope='session', autouse=True)
def openapi_db_setup():
    # setup
    DB_CONN.execute("REPLACE INTO openapi_user ...", [...])
    yield
    # teardown：无条件清理
    for uid in [main_uid, rl_uid, noperm_uid]:
        DB_CONN.execute("DELETE FROM openapi_user_path WHERE user_id = %s", [uid])
    for user_code in [TEST_USER, TEST_RL_USER, TEST_NOPERM_USER]:
        DB_CONN.execute("DELETE FROM openapi_user WHERE user_code = %s", [user_code])
```

## 11. Allure 报告标注规范

### 11.1 标注方式

| 标注 | 用途 | 使用位置 |
|------|------|----------|
| `@allure.feature('模块')` | 功能模块分类 | 测试类/函数 |
| `@allure.story('场景')` | 测试场景 | 测试类/函数 |
| `@allure.step('步骤')` | 操作步骤 | 方法级装饰器 |
| `allure.dynamic.title(...)` | 动态标题 | 运行时（Excel 模式自动设置） |
| `allure.dynamic.description(...)` | 动态描述 | 运行时 |
| `allure.dynamic.parameter(...)` | 参数记录 | 运行时 |

### 11.2 Excel 驱动模式（自动标注）

`api.test()` 内部自动设置：
```python
allure.dynamic.title(f"{case_dict['测试内容']}")
allure.dynamic.suite(f"接口:{case_dict['接口名']}-{case_dict['路径']}")
allure.dynamic.feature(f"{self.name} {self.base_url}")
allure.dynamic.story(f"{case_dict['接口名']}-{case_dict['路径']}")
```

无需手动标注。

### 11.3 纯 Python 模式（手动标注）

**✅ 正例**（参考 `test_competition_list.py`）：
```python
@allure.feature('OpenAPI 业务-赛事列表')
@allure.story('正常请求')
def test_competition_list_normal(openapi, default_updated_after):
    ...
```

### 11.4 规则

- **纯 Python 模式必须标注 `@allure.feature` 和 `@allure.story`**。
- **feature 命名**：`{服务名}-{功能模块}`，如 `OpenAPI 业务-赛事列表`。
- **story 命名**：场景描述，如 `正常请求`、`缺少参数`、`分页参数`。

## 12. 代码风格规范

### 12.1 import 分组顺序

```python
# 1. 标准库
import json
import logging
from pathlib import Path

# 2. 第三方库
import allure
import pytest
from json_tools import diff

# 3. 项目内模块
from apis import DataBff
from common.data import DB_CONN, CaseDict
from settings import TEST_DATA_DIR
```

### 12.2 命名

| 元素 | 风格 | 示例 |
|------|------|------|
| 变量/函数 | snake_case | `match_date`, `get_competition_list` |
| 类 | PascalCase | `DataBff`, `OpenApi` |
| 常量 | UPPER_CASE | `BUSINESS_PATHS`, `TEST_USER` |
| 私有方法 | _前缀 | `_compute_auth_headers` |

### 12.3 类型标注

Python 3.12 风格，使用 `dict|list` 而非 `Dict|List`：

```python
def get_asdict(self, sql: str, args=None) -> list[dict]:
    ...

def update(self, table: str, update_dict: dict, query_dict: dict) -> int | None:
    ...
```

### 12.4 docstring

公开方法必须有 docstring，说明参数和返回值：

```python
def get_competition_list(case_dict: CaseDict):
    """查询赛事列表的数据处理器。

    前置：根据参数从 DB 查询预期结果。
    后置：无。
    """
```

### 12.5 日志

使用 `logging.getLogger()`，不要用 `print` 做日志（调试输出除外）：

```python
import logging
logger = logging.getLogger(__name__)
logger.info(f'{route}用时:{elapsed:.2f}秒')
```

### 12.6 禁止项

- 禁止 bare `except:`（除非极其特殊的兜底场景）。
- 禁止 `import *`（`__init__.py` 导出除外）。
- 禁止在测试代码中硬编码服务地址、数据库密码等敏感信息。
- 禁止在 Generator 后置逻辑中省略 `try...finally`。
