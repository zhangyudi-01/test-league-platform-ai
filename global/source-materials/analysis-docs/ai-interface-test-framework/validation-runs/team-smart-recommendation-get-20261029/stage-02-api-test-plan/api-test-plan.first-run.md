# 球队智能推荐查询接口测试方案（第13轮）

> **接口**：`GET /relations/team/recommendations`，operationId `recommend`
> **测试边界**：仅验证接口返回与可观察数据库副作用；第13轮需求中的页面搜索、标签、选择、匹配保存和返回交互不属于本接口。
> **预期依据**：已确认的第13轮适配口径；OpenAPI 和现有 SQL/脚本中“最近10场”属于待更新旧基线。

## 一、请求与响应约定

- 请求参数：人工球队 `teamId`、目标源 `currentDataSource`。`currentDataSource=1` 时 A=贝泰、B=纳米；`=3` 时 A=纳米、B=贝泰；`=2` 成功返回 `data=[]`。
- 成功：HTTP 成功响应体 `code=0`、`message=OK`；`data` 是推荐候选数组，无候选时为 `[]`。
- 错误：缺少 `teamId` 返回 `code=2/message=teamId不能为空`；缺少或非法 `currentDataSource` 返回 `code=2/message=当前数据源不存在`；球队不存在返回 `code=2/message=球队信息不存在`。服务异常为 `code=31`，具体系统详情不作固定断言。
- 每个成功候选应包含 `sourceType`、`sourceTeamId`、`teamNameZh`、`teamShortNameZh`、`teamNameEn`、`recommendCount`、`matchStatus`、`checkStatus`、`manualTeamId`。OpenAPI 未标 `manualTeamId` nullable；其 `null` 预期只在与 SQL/当前字段语义一致的未匹配候选中验证。

## 三、接口不可覆盖的功能行为

第13轮规则中按钮显示/置灰、标签切换、搜索输入和重置、列表高亮、多选限制、匹配确认弹窗、保存后停留页面及返回行为需要真实页面交互验证，不列为本接口测试点。接口执行完成后再依据实际通过的 Facet 断言收敛功能残余。

## 四、自动化适配说明

- 序号13-24需要以数据库当前 `NOW()` 构造相对时间数据；现有脚本/fixture 使用静态日期，需在自动化设计中定义测试自有数据的动态时间准备与恢复方式。
- 序号9-12需验证赛季资格先于窗口选择；现有推荐 SQL 是旧 Top-10 并且先取窗口后桥接，不能直接作为新预期。
- 当前测试工程已有 `DataBff`、Excel `api_test_data()`、DB 查询和 generator 前后置能力；API 行为可观察，动态时间是数据准备适配，不是 API 不可测。
- OpenAPI 未给 `manualTeamId` 的 nullable 标记；序号35须以已审核字段语义和接口实现核实结果为准，不能只因 JSON schema 缺项而漏测。

**状态：ready for review。**本方案只覆盖一个 GET operation；SQL oracle、动态数据闭包、Excel 行与 pytest 函数映射留给自动化设计阶段。
